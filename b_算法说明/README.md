# b. 算法说明

本文件说明"怎么算"。链路：任务定义 → 队列与划分 → 特征 → 模型与训练 → 报警策略 → 评测协议 → 流式推理 → 复现命令；文末图 `fig16_architecture.png` 是同一链路的图示。

## 2.1 任务定义：统一成"看过去 300 s，预测未来 300 s"

把 6 个临床风险写成同一个判读问题——**观察过去 300 s 的信号，预测未来 300 s 内是否会出现"事件分钟"**。这样一套特征矩阵可服务全部终点，也才有"多模态监测"而不是"多个独立分类器"。

| 参数 | 取值 |
|---|---|
| 时间网格 | 1 Hz，跨设备零阶保持，最大陈旧度 15 s |
| 观察窗 | 300 s（另设 900 s 长窗做消融） |
| 预测视界 | 300 s（另评 600 / 900 s） |
| 决策步长 | 30 s |
| 事件定义 | 某生理量连续 ≥ 60 s 越限（按 1 Hz 计，窗口内 ≥90% 采样越限） |
| 病例有效性 | ≥50% 时长有有效 MAP；拒绝 >24 h 的异常时间戳记录 |

| 终点 | 信号 | 阈值 | 方向 | 本轮是否评测 |
|---|---|---|---|---|
| 低血压 hypotension | MAP | 65 mmHg | 低于 | ✔ |
| 低氧 hypoxemia | SpO2 | 90 % | 低于 | ✔ |
| 心动过缓 bradycardia | HR | 50 bpm | 低于 | ✔ |
| 心动过速 tachycardia | HR | 120 bpm | 高于 | ✘ 已实现未评测 |
| 通气不足 hypoventilation | 呼吸频率 RR | 6 /min | 低于 | ✔（需功能通道） |
| 高碳酸血症 hypercapnia | 呼气末 CO2 | 50 mmHg | 高于 | ✔（需功能通道） |

终点定义写在 `remote/build_dataset.py` 的 `ENDPOINTS` 表中，评测脚本导入同一份定义，不另写一份。

## 2.2 队列与划分

- 全部窗口 **1,553,854 个 / 3,495 例**；功能类终点（通气不足、高碳酸血症）只在有对应通道的 **2,500 例**上评测；
- **病例级互斥**划分 90 % / 10 %：fit 2,831 例、val 314 例、test 350 例（功能终点为 2,025 / 225 / 250）；
- 阈值与超参只在 val 上选，**test 只读一次**；
- 特征只用观察窗内信息，标签只看未来窗——这条边界是"无未来信息泄漏"的全部内容。

## 2.3 特征：67 维基础特征 + 波形增量

每个信号在 300 s 窗内取 9 个统计量：覆盖率、均值、标准差、最小值、最大值、末值、**每分钟斜率**、最近 60 s 末值、最近 60 s 均值；再加 3 项跨信号特征（`map_below65_frac` 低于阈值时长占比、`map_gap` 末值−65、`t_min` 术内时间）与 `n_tracks`。

- **7 个信号 × 9 = 63，+ 3 + 1 = 67 维**（与 `p0_dataset.log` 的 `numeric_feats=67` 一致）；
- 对照模型 `map_only` 只用 MAP：9 + 2 = **11 维**；
- 增量模态：PPG 波形 55 维、有创动脉压波形 55 维（同一 30 s 块网格上的脉搏形态、灌注与变异性特征）；
- 功能通道特征统一加前缀 `fn_`，**独立成组**，不与基础 67 维混同——"新通道是否带来增量"才可归因。

## 2.4 模型与训练

- **LightGBM GBDT** 二分类，验证集早停，主结果固定 seed=42；
- 多种子复现（`../d_运行结果/logs/verify_seeds.log`）：seed 42 / 7 / 2024 / 12345 的测试集 AUROC 分别为 0.9537 / 0.9519 / 0.9602 / 0.9552，结论不依赖单次随机种子（该检查覆盖低血压终点）；
- 训练后同时导出特征重要度，供报告绘图与归因。

## 2.5 报警策略：从"逐窗分数"到"监护仪报警"

单窗概率不是报警。进入需**连续 `persist` 个窗口**超阈，退出需概率落到 `clear_factor × 阈值` 以下（**回差**），再由 `remote/alarm_policy.py` 的 `alarm_runs` 归并成报警段。三档策略给出（检出率，假报警/小时）的帕累托前沿：

| 策略 | 检出率 | 假报警/小时 |
|---|---|---|
| persist=1 | 98.03% | 0.58 |
| persist=2 | 96.87% | 0.22 |
| persist=3 | 92.65% | 0.10 |

信号质量门控（`remote/quality_gate.py`）另测：可用窗口占 94.49%，假报警 0.22 → 0.21，检出事件 1331 → 1267——**收益极小、代价明确**，因此不作为默认。

## 2.6 评测协议

- **窗级**：AUROC、AUPRC、准确率、灵敏度、特异度、平衡准确率；
- **事件级**：检出率、首次报警延迟、报警数/小时、假报警/小时（按测试集实际小时数归一）；
- **显著性**：病例级重采样配对 bootstrap（500 次）给差值区间，McNemar 给判别差异；
- **提前量**：必须做**配对比较**（同一事件内逐事件比较提前秒数），不能分别取中位数再相减——后者曾把 0 s 的差异伪装成"+1.65 min"，是本项目被自己的检验推翻的结论；
- **校准与临床效用**：Brier、ECE、决策曲线净收益；
- **工作点**：给出验证集上多档灵敏度对应的阈值，避免"只看 0.5"的假象。

## 2.7 流式推理（在线可用性）

`remote/stream_monitor.py` 按样本喂入、即时输出风险与报警。关键设计：**直接导入离线实现**（`build_dataset.window_row`、`alarm_policy.alarm_runs`），不重写第二份，从结构上杜绝线上/线下漂移。

核验结果（`../d_运行结果/logs/stream_check.log`）：3 例、67/67 特征完全一致、分数最大偏差 2.973e-08、单次决策中位延迟 1.25–2.16 ms（p95 ≤4.07 ms）——同一份模型可在线运行，且与离线数值等价。
